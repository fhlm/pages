# 圣地巡礼 / 出行行程规划工作流（可复用模板）

> 从需求到上线网页的完整流水线，2026-11-22 青ブタ×孤独摇滚湘南巡礼项目沉淀。
> 后续做类似规划（任何主题的行程页）时按本流程走，产物结构可直接复制改名。

## 0. 产物形态

```
一个主题目录 = 1 份 xlsx（数据源）+ 1 个 gen xlsx 脚本 + 1 个 gen html 脚本
            + index.html（单文件自包含网页）+ README
仓库根 index.html = 导航卡片墙 → 各主题子目录
```

- 网页零依赖（CSS/JS 内联），手机友好，点卡片看详情弹层。
- Excel 是唯一数据源，网页由脚本生成，**永远改脚本/Excel，不手改 HTML**。

## 1. 需求确认清单（开工前问齐）

| 项 | 说明 | 本例取值 |
|---|---|---|
| 起点 / 终点 | 精确到站名，住处→站步行时间也要 | 住吉站 → 羽田T3 |
| 硬约束 | 航班/新干线等不可移动时刻 | 23:55 起飞，提前 2h 到达 |
| 时间预算 | 起床时间、最晚出门 | 指定起床时间版 |
| 饮食偏好 | 想吃的类型 / 指定地区 | しらす丼、晚饭龟户→后改辻堂 |
| 追加主题 | 其他作品联动 / 购物 | 孤独摇滚 S1E8、Animate 立牌 |
| 同行人数 | 影响缓冲（2人 +15~25分） | 1人 |

## 2. 圣地调研

1. **攻略聚合文**先扫一遍拿全清单（web_search → web_fetch），景点编号建账。
   - 坑：部分站点 JSON 里嵌正文，用正则 `"body": "(.*?)",\s*"url"` 抽取；anitabi.jp 有反爬（403），换文字攻略源。
2. **官网核实**每个关键点的：营业时间 / 票价 / 最后入场 / 定休日 / 是否需预约。
   - 水族馆、展望台、灯饰季这类「季节性信息」必须查官网当日版本。
3. **官方联动**单独确认（站名板 / 列车涂装 / 期间限定）：记下准确期间，判断出行日是否在期内。
4. 每点标注 `✓已排 / 备选 / 放弃(原因)`，放弃也要记原因（不顺路 / 时间不够 / 已拆）。

## 3. 交通时刻核实（行程的骨架）

用 **Yahoo!路線情報** 查到「出行当天」的实际班次（不是平日平均估计）：

```
https://transit.yahoo.co.jp/search/result?from=<urlencode站名>&to=<urlencode站名>
  &y=2026&m=11&d=22&hh=8&m1=0&m2=9&type=1&s=0&x=1&dispCount=1
```

- `y/m/d` 必须给实际日期（周末班次不同）；`hh/m1/m2` 是期望出发时分。
- 机场站注意区分同名站：`羽田空港第３ターミナル(京急)` 要带括号后缀。
- 每段记录五要素：**班次列表（含发车等级・行方向）→ 番线/站台 → 耗时 → IC票价 → 换乘次数**，外加 1~2 个后备班次。
- 末班核查：回程最晚一班的实际时刻写进「说明」Sheet，兜底方案（打车/过夜）一并写。
- 票价合计算预算行：IC 卡价为准，注意比旧估计高/低都要在卡片上标注 ⚠。

## 4. 时间表设计原则

- **班次是骨架，活动夹缝里填**：先定 8 段交通，再往中间填巡礼/餐饮。
- 换成实查班次后全天会漂移 7~10 分，属正常，重排受影响段即可。
- **伸缩点**显式标注：哪些活动可压（早餐 25→20分）、哪些可舍（岩屋、エスカー）。
- 自然约束查当天：日落时刻决定登岛时间窗；灯饰/联动期间决定取舍。
- 每段活动给 Plan B（赶不上 A 班就如何如何），写进行程备注。
- 两人出行 +15~25 分缓冲，并写走散规则。

## 5. Excel 生成（gen_*_xlsx.py，openpyxl）

Sheet 划分（可按主题增删）：

| Sheet | 内容 |
|---|---|
| 主时间表 | 时间轴行（时间/类型/行程/说明/费用），节点行灰底、餐饮行橙底 |
| 圣地清单 | 全编号+✓状态+访问要点 |
| 说明与备选 | 交通券/预算/末班核查/巡礼礼仪/备选方案 |
| 预约清单 | 哪些要提前买/订，哪些现场买 |
| 主题Sheet | 第二部作品等（如孤独摇滚圣地） |

- `put(ws, r, values, fills={列: 颜色}, bolds={列})`——**fills 的值必须是颜色字符串常量**（如 `C_OK`），传嵌套 dict 会 openpyxl TypeError。
- 交通行「说明」列用 `\n` 分行结构化（这直接决定网页卡片样式，见 §7 格式契约）。
- 合计行单列交通/门票/餐饮预算。

## 6. HTML 生成（gen_*_html.py）

- 输出**单文件** `index.html`：`{}` 转义的 f-string 模板，内联 CSS/JS。
- 布局：渐变 hero → 毛玻璃 sticky 导航（tab 切换 section）→ Sheet1 竖向时间轴（`.tl`，时间胶囊+卡片），其余 Sheet 徽章卡片列表。
- 交互（JS 全在模板内）：点卡片开底部抽屉 modal（读 `.f/.chip` 的 innerHTML）；`#fab-now` 悬浮按钮显示实时时间、每 30s 标记 `.now` 当前时段并 scrollIntoView；`show(id, scroll)` 用 activeId 防止 tab 切换乱跳顶。
- 生成后校验：提取 `<script>` 存临时 js → `node --check` 验语法；正则计数关键元素（如 `card trans`、`pill on`）确认数量符合预期。

## 7. 交通卡片格式契约（说明列 ↔ 网页专用卡）

时间行 `类型=交通` 时，html 端走 `trans_html()` 专用布局，说明列按行解析：

| 行格式 | 渲染 |
|---|---|
| `班次：08:09発 笹塚行（1番線） → 08:31着 新宿4番線｜尾注` | 到发条：时刻大字+站台徽章；`｜尾注`（≤8字）转费用徽章，长尾注转备注 |
| `班次：10:58 / 11:12 / 11:26（约12分一班）` | 班次胶囊列表，与卡出发时刻相同的那粒 `.on` 高亮 |
| `后备：…` / `错过…` / `赶不上…` | 灰色小字后备行 |
| `⚠ …` | 橙色警示条 |
| `备注：…`（前缀会被剥掉） | 普通备注行 |

「行程」列格式：`A → B（线路名・方向，N分）`，正则 `TRANS_ROUTE_RE` 宽松匹配（线路名可缺省）。解析失败自动回退通用卡片，不会白屏。

## 8. 重点高亮（HL_RE）

`.fv` 文本过 `hl()`：按 HL_RE split → 逐段 escape → 奇数段包 `<b class="hl">`。关键词组：

`时刻 \d{1,2}:\d{2}` / `金额 [\d,]+円` / `时长 \d+分・\d+小时` / `最后入场` / `末班…` /
`直达・0换乘・直通・当駅始発` / `实查班次・后备` / `赶不上…` / `✅・⚠`

新增卡片类型想高亮，往 HL_RE 加分支即可，CSS 只有一个 `.hl`。

## 9. 发布流水线

### 本地

```powershell
python gen_xxx_xlsx.py ; python gen_xxx_html.py   # 产物按脚本内 OUT 落盘
# 把生成的 index.html + xlsx 覆盖到仓库主题目录（不要连带本地路径的脚本副本）
git add -A ; git commit ; git push
```

push（受限网络下 https 443 可能被 reset，此时改走 SSH；ssh 可执行文件路径含空格时整段加引号）：

```powershell
$env:GIT_SSH_COMMAND = '"<git 自带 ssh.exe 绝对路径>" -o StrictHostKeyChecking=accept-new'
git push origin master   # stderr 的 NativeCommandError 是 PowerShell 误报，看 master -> master 行
```

### CI（.github/workflows/）

- `deploy.yml`：官方 Pages 三件套（actions/configure-pages + upload-pages-artifact `path: "."` + deploy-pages），push 即部署。
- `regen.yml`：push `aobuta/*.xlsx`（或手动）→ `force_regen.py` → 只 commit 生成的 index.html（`[skip ci]`），deploy 随后跑。
- `force_regen.py`：读 xlsx → 把 gen 脚本文本里的本地绝对路径替换成仓库相对路径后 runpy 执行，产物落在主题目录。

### 首次启用（一次性，人工）

Settings → Pages → Source 选 **GitHub Actions**。workflow 无法自动建站（`Resource not accessible by integration`，加 administration:write 也没用），必须手动点一次。

### 上线验证

```powershell
$r = Invoke-WebRequest 'https://<user>.github.io/<repo>/<子目录>/' -UseBasicParsing
$r.StatusCode; [regex]::Matches($r.Content,'关键词').Count   # 与本地产物计数对齐
```

## 10. 踩坑速查（本项目实录，已脱敏）

| 坑 | 处置 |
|---|---|
| openpyxl `put()` fills 传 dict 嵌套 → TypeError | fills 值用颜色字符串常量 |
| PowerShell 控制台中文/日文文件名乱码 | 显示问题，`Get-ChildItem` 验证文件本体正常 |
| git add -A 把临时副本带进仓库 | 同步仓库只 copy index.html + xlsx |
| edit old_string not found | 前一步已改过该段，锚点错位；重读文件取新锚点 |
| force_regen 后 xlsx 有 diff | 先比对内容：时间戳-only 可 restore，真实内容变更要入仓 |
| 首次 Pages 部署 workflow 三连败 | 自动建站无权限，人工启用一次即好 |
| git push 报 NativeCommandError | PowerShell 把 stderr 当错误，看末行 master->master |
| Yahoo 站名带同名歧义 | 加括号后缀，如 `羽田空港第３ターミナル(京急)` |
| 估时刻 vs 实查班次差 7~10 分 | 一律以出行日实查为准，全天骨架重排 |

## 11. 隐私红线（push 前自查，硬性规则）

公开仓库 = 全网可见。push 前对整个仓库 grep 自查，任何一项命中都不许推：

| 类别 | 禁止内容 |
|---|---|
| 本机路径 | 盘符绝对路径（如生成脚本里写死的输出目录）、用户名目录 |
| 身份信息 | 真实姓名、邮箱、公司/内网域名、内网 IP、机器名、SSH 路径 |
| 生活轨迹 | 住处位置、住处→车站步行时长、「实测距离」等表述、作息细节（前一晚活动等） |
| 关联账号 | 其他平台的用户名、主页 URL（导航页里的署名除外，需本人确认） |

推荐自查正则：`[A-Za-z]:\\（盘符路径）|用户名|@gmail|@qq|内网IP段|住处|实测|前一晚`（按需增删），
`git grep -n <pattern>` 只查已跟踪文件；历史提交里若有泄露需改写历史或删库重建。

行程内容本身的脱敏口径：
- 「住处 → 住吉站」改为「出发站：住吉」，步行时长删去（那是定位住处的半径信息）。
- 作息类行（起床/出门）整行删除或改为「出发站集合」。
- 「用户实测距离」「前一晚看 Live」这类出处/生活背景注释一律删。
- 圣地清单里「起点（已确认）」行改成只写站名，不带住处信息。

## 12. 新主题复制清单

1. 复制 `gen_aobuta_xlsx.py` → 改名 `gen_<主题>_xlsx.py`，重写 Sheet1 rows 与清单 Sheet。
2. 复制 `gen_aobuta_html.py` → 改 OUT/标题/hero 文案，`NAV_ICONS` 与 Sheet 名对齐；交通卡正则族原样可用。
3. 新建子目录（或直接在根）：放 xlsx + 两个脚本 + 生成的 index.html。
4. 根 `index.html` 导航墙在 `<!-- 新页面卡片加在这行注释下面 -->` 处加卡片。
5. §2~§4 调研做扎实 → §9 推送上线。
